# apps/web

Rules for the React PWA. The root `CLAUDE.md` still applies.

- **Layout (docs/development.md §15.5):** code is grouped by feature. `src/features/<area>/` (`auth`, `jobs`, `evidence`, `profile`, `resume`, `sources`) holds the area's page, the components only it uses, and their tests. `src/components/` is only for pieces more than one area uses — move a component there when a second area needs it. The app frame is `src/layout/`, hooks `src/lib/hooks/`, test helpers `src/test/`. Tests sit beside their file (`JobRow.test.tsx`), never in `__tests__/`.

- **Web auth (`apps/web/src/lib/api.ts`):** the access token lives in a module variable only — never localStorage/sessionStorage. The session is restored on load from the refresh cookie. All refreshes go through `refreshSession()`, which is single-flight in the tab and wrapped in a `navigator.locks` lock across tabs: two concurrent refreshes with the same cookie would trip the API's reuse detection and revoke every session. Never call `/auth/refresh` directly.
- **Web data:** server state via TanStack Query hooks in `src/lib/queries.ts`. Request bodies are validated client-side with the same `@shortlist/shared` schemas the API uses. Response types are hand-written in `src/lib/types.ts` (dates as ISO strings). Verification is never optimistic — the UI shows "verified" only after the server confirms.
- **Web styling:** use the semantic color tokens (`bg-surface`, `text-muted`, `bg-apply-bg`, … from `apps/web/src/index.css`) and the primitives in `src/components/ui.tsx` — never raw Tailwind palette colors (`slate-500`), or dark mode breaks. Icons from `lucide-react`. Mobile design (docs/web-design.md §8.4.1): primary buttons and any filled surface carrying text use `bg-accent-strong text-on-accent` (the brand `accent` is for rings, switches, icons and progress — it is only 3.8:1 under white text, docs/web-design.md §8.6); text sizes and corner radii come only from the named scales in `index.css` (`text-caption`/`footnote`/`body`/`headline`/`title`/`large-title`, `rounded-sm`/`md`/`lg`/`sheet`/`full`, docs/web-design.md §8.6) — `src/test/design-scale.test.ts` fails on `text-sm`, `text-[13px]`, `rounded-xl` and the like; form controls use `INPUT` (`border-input-border`, `text-control` 16px — never smaller, or iOS Safari zooms on focus); a selected segment, chip or tab uses `SELECTED` from `ui.tsx`; server set-up details (env vars, commands, doc sections) never go in user-facing text — put them in `AdminNote` (`components/AdminNote.tsx`) under plain words and a real action; a setting that saves on change shows `SaveStatus`; a failure toast passes `tone: 'error'`; anything fixed to the bottom of a phone screen registers with `useBottomInset()` and positions with `bottomAbove()` (`lib/hooks/useBottomInset.ts`) so it stacks instead of overlapping; style a navigating link as a button with `buttonStyles()`; overlays use `Sheet` (native `<dialog>`), never a hand-made modal — pass `title` (plus `description`/`icon`) and don't repeat the title or add a Cancel/Done header in the content, `Sheet` draws the header and Close; screen-to-screen pushes go through `PushLink` / `pushNavigate()` (`lib/navigation.ts` — react-router's `viewTransition` prop does nothing under `<BrowserRouter>`); swipe gestures keep `touch-action: pan-y pinch-zoom` so scrolling and pinch-zoom stay native; appearance (System/Light/Dark) is `lib/theme.ts` + the pre-paint script in `index.html` — dark tokens must stay under both the media query and `[data-theme='dark']` in `index.css`; page titles use `PageHeader` (it carries the phone's account button, so page tests mock auth with `vi.mock('../auth/AuthProvider', () => import('../../test/signed-in'))` from a `features/<area>/` file). Job list state belongs in the URL (`useListState`), not component state. To hide a component responsively, wrap it — a `hidden` class on an element whose own classes set `display` (e.g. Button's `inline-flex`) loses.
